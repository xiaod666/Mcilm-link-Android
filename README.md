# MciLm-link 安卓版 (Android Client)

> **项目简介**：本项目是基于 MciLm-link 联机引擎（C ABI 动态库）构建的 Android 原生宿主客户端。通过 JNI 与底层 C 库进行深度交互，实现了联机房间的创建、加入、状态监控、实时文字聊天、语音联机、Minecraft 局域网广播、文件同步、成员列表轮询、事件驱动 UI，平台生态功能（公告/活动/邀请/反馈），以及“后台全局保活与防崩溃分发机制”。

## 二、 技术栈

- **UI 框架**：Jetpack Compose + Material 3 (深色主题，现代化 UI)
- **架构模式**：MVVM + Repository + 协程 (Coroutines) + 状态流 (StateFlow/SharedFlow)
- **网络请求**：Retrofit + OkHttp + kotlinx.serialization
- **本地存储**：EncryptedSharedPreferences (强加密持久化 Token 与多账号密码)
- **Native 桥接**：C++ JNI (动态 dlopen/dlsym，含 OOM 内存保护)
- **音频引擎**：AudioRecord/AudioTrack (16kHz/mono/16-bit LE PCM，含国产 ROM AEC 降级兜底)
- **后台保活**：Foreground Service (前台服务) + 电池优化忽略与自启动双重引导
- **日志管理**：外部私有存储持久化 (自动脱敏、独立分卷、UI 支持暂停与分类过滤)
- **辅助功能**：二维码生成与扫码 (ZXing / ScanContract)、智能正则解析、SHA-256 加密校验
- **代码安全**：Release 全面开启 ProGuard 混淆与资源压缩 (ShrinkResources)

## 四、 核心机制说明

### 1. 多账号管理与智能免密安全策略
- **多账号快捷登录**：登录页支持本地加密保存最多 5 个账号，独立展示为“账号选择”列表。
- **智能免密（3+1 策略）**：勾选记住密码后的前 3 天内可无感快捷登录；超过 3 天后，强制要求隔天（间隔 24 小时）重新输入密码验证。
- **安全熔断防绕过**：当服务器端判定当前 Token 失效（强制下线/重置密码）或开发者强制覆盖 Token 时，App 会自动销毁对应的本地免密密码。即使再次点击该账号，也会强制要求手动输入密码，彻底堵死盗号者利用本地密码静默续签的漏洞。

### 2. 全局后台保活机制 (Foreground Service)
- 在用户登录成功后，自动启动 `LinkKeepAliveService`（声明为 `dataSync` 类型）。
- 首次登录会弹出引导框，引导用户关闭电池优化并尝试跳转自启动白名单（弹窗仅弹一次，后续静默）。

### 3. 计费闭环与权益控制 (Billing & Limits)
- **静默签到**：登录成功及开房前自动调用 `/api/user/checkin`。如果成功领到时长，会通过 Snackbar 提示用户。
- **权益硬拦截**：开房输入人数时，与 `roomMax` 联动。普通用户输入超出权益，直接无法输入并弹出 Toast。
- **耗尽警告**：在房巡检发现 `can_host=false` 时，顶部弹出红色横幅“时长耗尽，新玩家无法加入”。

### 4. 网络抗波动与防假死机制 (Network Resilience)
- **断网 5 秒缓冲**：网络丢失时不再瞬间断开联机，而是给出 5 秒缓冲期。期间网络恢复则无缝续连。
- **节点延迟监控**：通过解析底层选点日志，实时提取并渲染当前节点的 Ping 延迟（绿/黄/红颜色预警）。
- **重连防撞库**：断线时强制调用 `linkStop` 杀死底层协程，重连循环增加 3 秒退避。

### 5. 交互防抖与 UI 保护 (UX Protection)
- **防连点**：ViewModel 层引入 500ms 动作锁。
- **返回键拦截**：在 Loading 状态或联机中拦截物理返回键，强制弹出安全确认框。
- **状态防丢失**：表单状态全面引入 `rememberSaveable` 与 `mapSaver`，旋转屏幕或切换后台不丢失数据。
- **防输入法崩溃**：去除登录页自动抢焦点逻辑，彻底杜绝模拟器上的 Native 闪退。

### 6. 现代文件同步体验 (SAF)
- 接收文件时拉起 `CreateDocument` 选择目录，后台搬运私有目录文件。
- **大文件拦截**：大于 100MB 的文件在发送前会被拦截并提示，防止传输超时崩溃。

### 7. 日志系统与底层健壮性
- **日志面板**：支持暂停滚动、分类 Tab（全部/应用/内核/报错）以及分享。
- **JNI OOM 防护**：全局增加了严谨的 `GetStringUTFChars` 判空保护，拒绝底层空指针闪退。

## 五、 编译与运行指南

### 环境要求
- Android Studio Iguana 或更高版本
- NDK 26.1.10909125 (CMake 3.22.1)
- JDK 17

### 构建步骤
1. 打开项目，等待 Gradle Sync 完成。
2. 确保 `app/src/main/jniLibs/arm64-v8a` 目录下存在：`libmcilm_link.so`。
   *(注：若下载的是官方产物 `MciLm-link-android-arm64.so`，需重命名为 `libmcilm_link.so`。外置动态库在运行时由 `NativeLibraryManager` 下载后自动重命名映射。)*
3. 点击 `Build - Make Project`。
4. 准备一台真机设备（arm64 架构）运行应用。

> ⚠️ **模拟器特别说明**：官方库为 AArch64 汇编编译，x86_64 模拟器（如 MuMu、雷电）的翻译层可能无法处理某些 Go 汇编指令，导致 SIGILL 闪退。强烈建议在 ARM64 真实手机上进行完整联机测试。

# MciLm-link安卓版 更新日志

## [1.6.5-beta] - 2026-11-22
**核心主题：复查修复（构建阻断 / 导航竞态 / 重复订阅）与后台保活、断点续传、日志落盘加固**

### 🐛 Bug 修复
- **修复构建阻断**：`InviteScreen.kt` 中两行 `import` 在上次编辑时被合并成一行，导致整个模块无法编译。
- **访客进房的导航收敛**：自动进房增加「已登录 + 来源仅限首页 / 加入页」限制，避免会话中凭证失效跳到登录页后又被拉回房间（栈变成 `login→room`，用户回不去）；`handleAuthError` 在 Token 失效时补 `stopSession()`，把房间会话、巡检、音频与 `linkStop` 一并收掉，不再留下幽灵房间。
- **旋转不再重复处理事件**：`observeEvents()` 增加 `eventsJob` 守卫。此前 Activity 每重建一次就多挂一个收集器，聊天消息、房间事件、文件事件会被重复处理 N 次（表现为重复气泡、重复弹窗、重复 `bindRoom` / `linkStop`）。
- **旋转不再重复加载内核**：内核就绪状态移入 ViewModel，重建时跳过 `initialize`，不再重复联网检查动态库、也不再闪一下启动 Gate（进程被杀重启仍会正常初始化，不会误判库已加载）。
- **访客可以发文件、不再看到踢人按钮**：房间界面的文件能力不再读「开房表单」的本地开关（访客恒为关闭），改按底层 `isFileSyncSupported` 判断；成员弹窗的「踢出」仅房主可见。
- **公开房快速加入不再闪加入页**：去掉「先跳加入页、成功后再跳房间」的多余导航，成功后由 `AppRoot` 直接进房，失败则错误弹窗留在首页。
- **扫码 / 粘贴边界**：扫到无密码的房间会清空上一次输入的密码；解析旧版「（密码：xxx）」格式时只剥一个成对右括号，不再把密码自带的 `)` 吃掉。
- **取消 Loading 后仍能重复开房**：开房 / 加房协程用 `roomOpJob` 记录，进行中直接拒绝重入；点「取消操作」会连协程一起取消，并在 JNI 返回后补一次 `linkStop`，避免留下界面看不见的幽灵房间。

### 🛠️ 优化与重构
- **断点续传补全（含 Gitee）**：服务端未提供资产大小时也能按本地已有字节发 `Range` 续传；总长度改用 `Content-Range` 解析，进度条不再恒为 0%。
- **下载取消即时生效**：下载循环内加入 `ensureActive()`，job 结束时兜底 `cancelInFlight()`，用户取消或退出页面后不会在后台把整包下完。
- **后台保活真正生效**：改用 `START_NOT_STICKY`，进程被判死后不再残留「联机会话正在后台保持」的通知；`startForeground` 增加异常兜底，避免 Android 12+ 后台启动限制直接崩溃；唤醒锁每 6 小时自动续期（单次 12 小时），Wi-Fi 锁失败会在续期时重试。
- **日志落盘兜底**：外置私有目录不可写时回退到内部私有目录，并同步补齐 FileProvider 路径，「崩溃必落盘」不再因存储异常静默失效。
- **日志面板与更新弹窗细节**：过滤结果按 `logRevision` 缓存（满 1000 条或点「清空」后都能正确刷新，无关重组也不再重复过滤 1000 条）；更新弹窗 `Downloaded` 状态补「稍后」按钮。
- **记住账号读取加锁**：`getRememberedAccounts()` 补 `@Synchronized`，避免读取时的过期清理回写覆盖并发的保存 / 删除。

- `versionName` 升级至 `1.6.5-beta`，`versionCode` 升级至 `19`。
- **发布提示**：若在 GitHub 将本次 Release 标记为 Pre-release，而客户端 `update.allow.prerelease` 仍为默认 `false`，应用内更新会忽略该版本；需要灰度时请在 `local.properties` 打开该开关，或直接发布为正式 Release。

## [1.6.4] - 2026-11-22
**核心主题：联机链路收尾、日志与更新体验修复、崩溃落盘与后台保活补齐**

### 🐛 Bug 修复
- **访客加入后进不了房间界面（P0）**：`room` 路由虽然注册了 `HostScreen`，但全工程没有任何 `navigate("room")` 调用，访客加房成功后仍停留在加入页，聊天、文件、成员、停止房间全部不可达。现在 `AppRoot` 监听 `roomId + isJoining` 自动进入房间，并把加入页从返回栈中替换掉；房间内标题、底部按钮与停止确认框按房主 / 访客区分文案。
- **复制房间信息与加入页解析不兼容**：复制出来的是「房间号（密码：xxx）」，加入页只认 `房间号 pass:密码`，粘贴后整串会被当成房间号、密码也拆不出来。现在复制内容与二维码统一为 `房间号 pass:密码`，加入页新增 `parseRoomText()` 兼容 ` pass:`、`（密码：xxx）`、`(密码:xxx)` 与纯房间号，扫码 / 粘贴 / 提交三处共用。
- **日志面板满 1000 条后停止刷新**：到达上限后是「删一条 + 加一条」，`size` 恒定使 `remember(size)` 永不失效，界面从此卡在旧列表上；首次打开还会因为读到上一帧的空列表而 `scrollToItem(-1)`。现在直接在组合期过滤 `SnapshotStateList`，自动滚动改用单调递增的 `logRevision` 触发。
- **全局 Loading 卡死无法取消**：`onDismissRequest` 与 `confirmButton` 都是空实现，任何一条忘记复位 `isLoading` 的路径都会把用户永久锁死。现在超过 12 秒出现「取消操作」，只复位 UI 状态、不打断后台请求，正常耗时内行为不变。
- **设置页「检查更新」绕过全局状态**：原先直接 `new UpdateManager()` 做一次性检查，只弹一个 Toast，`updateState` 毫无变化，首页红点与更新弹窗都不会出现，发现新版本后无法继续下载安装。现在统一走 `vm.checkForUpdate(silent = true, force = true)`，并把更新弹窗从 `HomeScreen` 提升到 `AppRoot` 全局渲染。
- **错误弹窗「重试」会删掉已记住的密码**：`retryLastAction()` 固定传 `rememberMe = false`，而 `login()` 在该分支会调用 `removeRememberedAccount()`。现在改为沿用该账号当前的记住状态。
- **轮换持久 Token 后新值被丢弃**：`rotateToken()` 的返回值此前被直接忽略，界面只提示「请保存好新值」却看不到任何值。现在写入 `UiState.rotatedToken`，设置页弹出只读输入框并支持一键复制到剪贴板。
- **公告列表重复 key 崩溃（P1）**：公告页用 `items(list, key = { it.id })` 渲染，服务端分页重叠或缓存重复时会抛 `IllegalArgumentException: Key was already used`。现在与公开房间一致，在下发 UI 前 `distinctBy { it.id }` 去重，未读数基于去重后的列表计算。
- **音频采集 `read == 0` 被误判为错误（P1）**：`if (n > 0) n else -1` 把「这一帧暂无数据」与「采集失败」混为一谈，引擎侧误判后表现为偶发断音。现在区分 `n > 0`、`n == 0`、负值三态。
- **APK 断点续传是死代码**：旧实现「缓存未命中就 `delete()`」，使 `startOffset` 恒为 0，Range / 206 / 416 分支永远走不到。现在保留残缺安装包真正续传，兼容服务端忽略 Range 回 200 的情况，416 改为循环重试一次（不再递归调用自身），最终仍走大小 + 签名双重校验。

### 🛠️ 优化与重构
- **主线程 JNI 与二维码卡顿**：`fetchFileTasks()` 的同步 `linkQuery("fs_tasks")` 会被事件收集器（主线程）直接调用，最坏情况每个 3 秒巡检 + 每个 `file_sync_*` 事件都在主线程解析 JSON；现在整体移到 IO 并加单飞守卫，避免底层卡住时协程堆积。二维码由逐像素 `setPixel`（512×512 = 26 万次）改为 `IntArray + setPixels`，并用 `produceState` 在 `Dispatchers.Default` 生成。
- **崩溃堆栈真正落盘**：工程此前既没有 `Application` 子类，也没有 `setDefaultUncaughtExceptionHandler`，`LogFileManager.writeCrash()` 是一段永远走不到的死代码。新增 `MciLmApp` 在进程启动最早期初始化日志并注册全局异常处理器，崩溃堆栈同步落盘后交回系统默认处理器；同时补齐崩溃路径的密码脱敏与 session 日志分卷。
- **后台保活名副其实**：`LinkKeepAliveService` 此前只挂了一条前台通知，锁屏后 CPU 仍会休眠，联机心跳 / 语音被系统挂起。现在进入房间时持有 `PARTIAL_WAKE_LOCK` + Wi-Fi 高性能锁（最长 12 小时），退房、停止保活、`onDestroy` 都会自动释放；只在房间会话中持锁，避免「仅登录没开房」也一直耗电。新增 `WAKE_LOCK` 普通权限。
- **记住账号去重加固**：登录页用 `items(accounts, key = { it.account })` 渲染，旧版本残留或异常写入产生的重复账号会直接闪退；现在读取时 `distinctBy` 去重，并把清理后的列表写回加密存储。
- 访客快捷加入的导航顺序修正：`roomId` 与 `isJoining` 在同一帧写入时不再先跳加入页、再跳房间，返回栈不会出现「房间 → 加入页」的错序。

- **升级提示**：本次新增 `Application` 类与 `WAKE_LOCK` 权限，旧安装包需要覆盖安装（重装）后才会生效。
